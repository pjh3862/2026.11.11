# data10-05 · 공정 재고 · C/T (구 생산진도율 자동화)

기초재고(한 번)와 현장 공정 실적(시작 · 멈춤 · 다시 시작 · 종료 단추)으로 아이템 · 공정별 현재 재고, 실제 걸린 시간(C/T), 공정별 일별 생산수량을 보여 주는 브라우저 도구

| 항목 | 내용 |
|---|---|
| 제출자 | 박주헌 |
| 과정 | 현장 데이터 디지털화 전문가과정 2차수 (2026) |
| 진행 단계 | 1단계(10-20) · 2차 실제 양식(10-21) · 3차 범위 재설정(10-28) · 4차 확인 답 반영(11-08) · **최종 기획서 v2.0 · 로그인 · 사용 승인 (2026-11-10)** |
| 주소 | https://data10-05.jobability.co.kr/ · 기획서 https://data10-05.jobability.co.kr/plan.html |
| 다음 개발 | 실적 공유 저장(여러 휴대폰 실적을 한곳에) |

> 3차(10-27 요청)에서 「기초재고 + 실적 + 고객사 발주서 → 생산진도율」을 「기초재고 + 실적 → 현재 공정별 재고현황」으로 좁혔습니다. 재고 체크 · 재고 과부족 · 생산진도율 페이지와 발주서 · 납품 · 실적 가져오기, 근무 투입조정 · 안전재고 산식은 뺐습니다. 샘플은 모두 **가짜 값**(고객사A · B, 품번 SMP-1001…)이고, 회사 이름은 리포에 적지 않습니다.

## 실행 방법

**온라인에서 바로 보기: https://data10-05.jobability.co.kr/**

처음 열면 대시보드에서 **「가상 샘플로 시작」** 을 누릅니다. 심어 둔 것 — 10-20 로봇 설비 정지(그날 로봇 생산 「적음」, 다음 날 잔업 「많음」, 그 여파로 10-21 사상 「적음」), SMP-4001(대형) C/T 가 김, 진행 중 타이머 2개(작업 중 · 멈춤).
실제로 쓸 때는 ① 설정에서 관리 아이템(엑셀 양식) ② 데이터 가져오기에서 기초재고(기준날짜 + 공정별 완료재고, 한 번) ③ 현장에서 휴대폰으로 실적 입력 순서입니다. 자료는 이 브라우저 안에만 저장됩니다(서버로 보내지 않음). 1 · 2차 판을 쓰던 브라우저는 열면 「저장 형식이 바뀌었습니다」 안내가 뜨고, 옛 자료는 JSON 으로 받을 수 있습니다.

내 PC 에서 열려면 `index.html` 을 더블클릭하거나, 폴더에서 `python3 -m http.server 8000` 후 `http://localhost:8000` 을 엽니다. 외부 CDN 을 부르지 않습니다(엑셀은 `vendor/` 의 SheetJS).

| 화면 | 하는 일 |
|---|---|
| 0 대시보드 | 고객사 · 그룹 · 상세그룹 · 품목 거르기, 공정별 · 모델별 완료재고 표와 그래프, **계산 보기**(기초재고 + 이 공정 실적 − 다음 공정이 가져감 = 완료재고), 실제 걸린 시간(C/T) 표와 그래프, 확인할 것(음수 재고 · 공정 순서 밖 실적 · 기준날짜 전 실적), 엑셀 내보내기 |
| 1 실적 입력 | **타이머** — 아이템 · 공정을 목록에서 골라 start, stop(멈춤) · restart(다시 시작), end 때 수량 → 실적 1건(C/T = 순작업 시간 ÷ 수량). 새로고침 · 화면 꺼짐에도 이어짐. **직접 적기** — 끝난 작업을 일자 · 수량 · 분으로. 최근 실적 · 지우기 · 엑셀 받기 |
| 2 데이터 가져오기 | 기초재고만 — 기준날짜(그날 아침) + 아이템 × 공정 완료재고, 화면에서 고치거나 엑셀 양식으로 넣기 |
| 3 공정 분석 | 공정별 일별 생산수량, 일 평균, 평균에서 30% 이상 벗어난 날(많음 · 적음)과 그날의 실적 |
| 4 AI 분석 | 계산된 공정 재고 · C/T · 벗어난 날만 담은 프롬프트(품번 · 고객사 별칭), 복사 · 붙여 넣기(선택: OpenAI 호환 서버로 보내기) |
| 설정 | 공정 이름(추가 · 이름 바꾸기 · 빼기), 관리 아이템(고객사 · 그룹 · 상세그룹 · 품목 · 품번 · 비고 + 공정 순서, 「출하」는 자동으로 마지막), 아이템 엑셀 양식 · 넣기 · 받기 — 엑셀은 **한 줄에 공정 하나**(… · 품번 · 비고 · 공정, 같은 품번의 줄을 위→아래 순서로 공정 순서로 읽음, 10-30 받은 실제 목록 모양). 옛 「공정 순서」 한 칸 양식도 읽음, AI 연결, JSON 백업 |

계산 규칙(기획서 12.2): 공정 P 실적 q → P 완료재고 + q, 아이템 공정 순서의 바로 앞 공정 − q. 첫 공정은 + q 만(원자재 재고는 고려하지 않음 — 10-30 답). 출하도 실적 입력에서 「출하」 공정 실적으로 적고(10-30 답), 마지막 공정 − q, 출하 누계 + q. C/T 는 작업 인원 수를 따지지 않습니다(10-30 답). 기준날짜(그날 포함)부터의 실적만 재고에 넣습니다.

- 로직 테스트: `node test/logic.test.mjs` (의존성 없음, 24개)
- **판 올리기(고칠 때마다)**: `node scripts/bump-version.mjs 2026-11-08.2` — index.html 의 모든 js · css `?v=` · logic.js · app.js 를 같은 값으로. 섞이면 화면이 「새 판이 나왔습니다 — 새로고침(Ctrl+F5)」로 멈춥니다. `--check` 로 같은지만 봅니다(로직 테스트도 봄)
- 샘플 파일 다시 만들기: `node scripts/make-samples.js` → `samples/` 2개(관리 아이템 — 실제 목록과 같은 한 줄에 공정 하나 모양, 값은 가짜 · 기초재고, 다시 읽어 확인)
- 브라우저 점검(선택): `PLAYWRIGHT_CORE=…/node_modules/playwright-core node scripts/check-browser.mjs` (판이 맞는 브라우저가 없으면 `CHROME=<실행 파일>`, `BREAK=1` 은 넘침 검사 자체 점검)
- 기획서 Word 다시 만들기: `python3 scripts/make-docx.py` (python-docx)

## 로그인 · 승인

1. 대문에서 **회원가입** — 회사 메일이나 개인 메일 + 비밀번호
2. 가입한 뒤 **사용 신청**
3. 관리자가 **승인**하면 도구가 열립니다. 승인 전에는 「승인 대기」 안내가 보입니다.

- 관리자는 처음에 과정 운영 계정이고, 요청자를 관리자로 올리면 요청자가 자기 팀원을 직접 승인합니다.
- 회원 표는 Supabase `data1005_members` 입니다(`supabase/auth.sql`).
- 내 PC(localhost)에서 열면 로그인을 건너뜁니다. 로그인 대문을 보려면 주소 끝에 `?auth=1` 을 붙입니다.
- 업무 자료(아이템 · 기초재고 · 실적)는 지금도 이 브라우저에만 저장됩니다. 로그인은 「누가 쓸 수 있는가」만 정합니다.
